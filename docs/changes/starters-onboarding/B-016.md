# B-016 Templates and the tile gallery
Backlog: B-016 · Tier: big · Areas: editor-shell, tiles-ui · Decisions: S0, S1, S2 and S3a answers in docs/plans/starters-onboarding.md
Output: unchanged
Package: no

## What changed
A new user can start without pictures of their own.
- **New** opens the **New tileset** popup: **Empty**, or **From template**, which lists **Collage**, the first template (6 tile groups, 6 operations). A template opens exactly as an Import does.
- **Every Add in Tiles opens the Tile gallery**: the 21 Collage pictures, plus **My tiles**, the author's own uploads (**Upload…**), kept across reloads. The picks become one new named group, or variants of an existing group.
- **The open tileset is kept across reloads**, with its pictures. Undo starts empty.
- **Opening a file can't be undone.** Import, a template and the reload each start a fresh history, and Import asks first unless the current tileset is blank.
- Nothing from the starters is fetched until it is asked for. Collage ships migrated to schemaVersion 4, with its photos re-encoded as WebP q90 (10.8 MB → 0.86 MB).

S3a (content and loader, no UI yet): the editor ships its first template, Collage, under `apps/editor/public/templates/collage/`. It was migrated to schemaVersion 4 by `migrate()`, and its embedded photos were re-encoded as WebP q90 (10.8 MB → 0.86 MB, approved by Pol by eye). A manifest, `public/starters.json`, lists the template and the 21 gallery pictures, with committed thumbnails. New `starters.ts` parses the manifest and loads a template or gallery pictures on demand. ImportPanel's open sequence is split into a pure `prepareArchive` (`import.ts`) and `adopt` (`adopt.ts`), so templates open exactly as an import does.
