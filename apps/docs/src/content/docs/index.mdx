A file-by-file reference for `packages/tileset` (`@fndvit/gen-tilesets`) and `apps/editor`,
for contributors and maintainers. `apps/demo` is out of scope.

**Every page is written from source code only:** `.ts`, `.svelte` and `*.test.ts`. No page is
written from the repository's Markdown files or the archived specification. When a source comment
cites the spec (`` `06` §9.2 ``, **C2**, **R8**), the page quotes or paraphrases the comment and
does not follow the pointer. Each page opens with a **Written from** line naming the files it was
written from, so you can check it against them.

Sidebar order within each section follows the pipeline: file → load → generate → draw for the
package, and import → document → draft/history → preview → export for the editor.

## How to read a module page

Every module page has the same shape:

1. **Overview**: plain language, no citations, no identifiers. Read this first to know what the
   file is for and where it sits.
2. **Try it**: on pages with a live story.
3. **In detail**: Purpose, Public surface, Inputs → outputs, Invariants, Callers / callees
   (from grep, with `file:line`), Tests, Gotchas & rejected alternatives, Review notes.

Line numbers were correct when the page was written. The **Written from** line tells you which
files to reopen when they drift.

## Keeping it honest

- `pnpm --filter @fndvit/tileset-docs build` runs `scripts/coverage.ts` first. It fails if any
  non-test `.ts` or `.svelte` file under `packages/tileset/src` or `apps/editor/src` has no module
  page whose **Written from** line names it by its full path.
- CI builds the site on every push, so a page that stops compiling, or a public entry point that
  stops typechecking under TypeDoc, fails the build.
- Nothing checks that prose still matches code. That is what the **Written from** line is for.
