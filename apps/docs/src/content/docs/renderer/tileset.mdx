## Overview

`<Tileset>` is how a Svelte page puts a tileset on screen. A host gives it a tileset file and,
optionally, a settings object. It generates the grid, places it for the box it was given, hides
tiles that would cover content the host asked it to avoid, and paints the result, on one canvas by
default or as one element per cell.

**Since 0.9.0 it is a thin wrapper over [`TilesetRenderer`](/renderer/renderer/)**, which does all
of that and works without Svelte. [`model.ts`](/renderer/model/) derives everything the renderer
draws. This component adds only what a Svelte host needs:

- props, and `bind:box`;
- options edited in place (a `$state` object) counting as a change;
- a placeholder in server-rendered HTML, so the page reserves the tileset's space before any
  script runs;
- a development check for the props that moved into `options` in 0.6.0.

The editor's preview is this component on the editor's file, and
[`<TileDecoration>`](/renderer/tile-decoration/) is the same kind of wrapper over
`TileDecorationRenderer`.

## In detail

### Purpose

The rules the renderer keeps, and so this component with it:

- **S1: one entry point.** It accepts a `TilesetFile` and calls `generate()` itself. Nothing in
  the package accepts a `Grid<TileState>` as an input.
- **S2: the editor's preview is this component** on the editor's file. Overlays draw *over* it,
  never instead of it. There is no preview mode.
- **S3: no validation on the draw path.** In production it has undefined behaviour on a file
  `validate()` would reject. A development build asserts validity once per file.
- **S7: no random number and no ambient state.** `loadSalt` is drawn once by the host, so the
  component has no draw to repeat.

### Public surface

Imported as `@fndvit/gen-tilesets/Tileset.svelte`.

| Prop | Type | Default | Meaning |
| --- | --- | --- | --- |
| `file` | `TilesetFile` | required | Parsed, valid, and held stable by the host (**S3**). |
| `options` | [`TilesetOptions`](/api/render/interfaces/tilesetoptions/) `\| undefined` | `undefined` | Every setting. Defaults are in `resolveOptions`; see [options.ts](/renderer/options/). |
| `box` | `HTMLElement \| null` | `null` | **Bindable.** `renderer.box`: the render box, for converting pointer events to render space. `null` until the renderer mounts and after teardown. |
| `...rest` | anything | none | Collected only so a development build can throw on a pre-0.6.0 prop (`seed`, `loadSalt`, `provider`, `onAssetError`, `substrate`). |

No events and no snippets. Callbacks go through `options.onAssetError`. The attributes a host can
select on are listed in [DOM hooks](/renderer/dom-hooks/).

**The root element is a `div[data-tileset-host]` with `display: contents`**, holding the render
box. It has no box of its own, so the render box's `width: 100%` resolves against the page's
element, and a flex or grid parent sees the render box as its item. Host CSS that selected the box
by position (`.hero > .tileset`) no longer matches it since 0.9.0; select `[data-tileset-box]`.

### How it drives the renderer

**One effect builds the renderer, then feeds it.** The first run builds a `TilesetRenderer` on the
host element; every later run calls `update({ file, options })`. One effect rather than a mount
effect plus an update effect: a mount effect reads nothing, so a constructor that threw on an
invalid prop was never retried, and a host that fixed the prop kept a placeholder for good.

- **The options are copied** (`copyOptions`), which reads every field a host could edit in place,
  so `opts.seed = "b"` on a `$state` object re-runs the effect. The renderer copies again in
  `update()`, for a host with no Svelte. The model's per-field memos stop an unchanged copy, so an
  inline `options={{…}}` re-running the effect per parent render regenerates nothing (**R12**).
- **The renderer is built and updated `untrack`ed.** Its development checks walk the whole file;
  tracked, they would make the effect depend on every field of a `$state` file in development only.
- **The id is `$props.id()`**, stable between server and client, so the server's reservation CSS
  and the client's agree.
- A second effect, which reads nothing, destroys the renderer on teardown.

### The server render

No effect runs on the server, so the component writes a **placeholder**: the render box exactly as
the renderer builds it before its first measurement. `placeholder.ts` computes it from the stages
before `generate()` (no grid is read), and `Placeholder.svelte` writes it out, with the
responsive reservation stylesheet when there are rules. The box carries `data-tileset-placeholder`.

On the client the effect calls `setAside(host)` before building the renderer, so the renderer's
first measurement is of its own box, and Svelte removes the placeholder in the same task, before
any paint.

**The DOM substrate's server HTML no longer holds cells** (0.9.0). The page reserves the same
height; cells and their `<img>` requests arrive at hydration. Cells in server HTML wait on a
server-side `renderHtml()`; `affineCellStyle` in `model.ts` is kept pure as its seam.

### Tests

`.svelte` components cannot be unit-tested in this repo, which is why the component is this thin:
everything it drives is tested in `renderer.test.ts`, `model.test.ts` and `placeholder.test.ts`.
The wrapper itself is covered by:

- `svelte-check`;
- `apps/demo/scripts/ssr.mjs`: for 7 cases × 2 widths × 2 DPRs, the server HTML reserves a pinned
  height (measured from the pre-0.9.0 component), hydration leaves one measured box and no
  placeholder, and nothing is logged;
- the demo's screenshot harness (`shots:capture`, `shots:diff`), 32 captures compared to a pinned
  baseline at 0 px.

### Gotchas & rejected alternatives

These are the renderer's now, but they explain what a host sees through this component.

- **No `width`, `config` or `layout` prop.** Every quantity is a fixed fraction of `Wpx`, so the
  host's CSS decides the width. Splitting the file across two props would let a host pair
  mismatched halves.
- **Placement by margin, not `transform: translate()`.** A transformed element is rasterised at
  sub-pixel precision, so at any fractional cell size every edge was antialiased, and two partial
  coverages "never sum to one", leaving a sliver of backdrop at every seam.
- **The canvas `height` is `auto` on purpose,** "the one line not to tidy". The canvas's intrinsic
  ratio makes the vertical scale equal the horizontal one.
- **The ratio is declared only until there is something to measure.** Declaring it permanently
  would show a hairline under the bottom row (canvas) or shave it (DOM).
- **The container wrapper exists only when rules do.** `container-type: inline-size` gives an
  element no width from its content, so in a shrink-to-fit context it would collapse.
- **The hit area is the rest pose.** Animate the `<img>` inside a cell, never the cell.
- **A plain block host was rejected** for `display: contents`: in a shrink-to-fit parent its width
  comes from content whose width is a percentage of it, so it collapses.
- **There were three substrates until 0.6.0.** `"svg"` showed a backdrop hairline at every shared
  edge and would have needed every feature built a third time.

The review notes on the pre-0.9.0 component (async rejections, `loadFailed`, stale comments) were
all fixed or became moot when its logic moved; they are in this page's git history.
