## Overview

This control appears in the attribute step of an open operation when the author picks a
number attribute such as Rotation, Scale X or Opacity. It is a track with two handles, under the
heading "Range" (the black bar of the block it sits in already names the attribute). The handles mark the lowest and highest value the operation will write, and
each cell gets a value between them according to its Source. Exact numbers can be typed in the
"From" and "To" fields underneath.

The handles may cross. Crossing them reverses the effect, which is the only way to invert a
Source. A "Values" toggle below chooses between **Continuous** (any value in between) and
**Stepped** (a fixed number of evenly spaced values, set in a "Steps" field). When the Source is
`constant`, the two handles become one, with a single "Value" field, because a fixed value is a
range whose ends are equal. Explanations, such as the track's domain, are hints on the labels.
When the two ends of a rotation range are the same angle, an advisory shows at the end of the
block.

The author never sees the word "mapping". In the editor's pipeline (import → document →
**draft**/history → preview → export), it edits the draft's numeric mapping.

## Try it

Pick an attribute to see its track, and tick *collapsed* to see what the editor shows under a `constant` Source. The editor's own stylesheet is not loaded here.

## In detail

### Purpose

The component edits a [`NumericMapping`](/api/index/interfaces/numericmapping/) for one
[`AttributeName`](/api/index/type-aliases/attributename/). The track spans that attribute's
authoring range from [controls/mapping.ts](/editor/controls-mapping/). The header comment lists
three rules "each easy to get backwards": the handles cross rather than clamp; `steps` is a
separate control whose absence means *continuous*; the handles collapse to one under `constant`.

### Public surface

| Prop | Type | Default | Meaning |
| --- | --- | --- | --- |
| `target` | `AttributeName` | required | Which attribute's track to draw. |
| `mapping` | `NumericMapping` | required | `{ range: [a, b], steps? }`. |
| `collapsed` | `boolean` | required | One handle, writing both ends. |
| `onChange` | `(mapping: NumericMapping) => void` | required | Receives the whole new mapping. |

### Inputs → outputs

- `track = trackFor(target, mapping.range)`: a soft track widens to contain the current values;
  a hard one does not. The slider step is `(max − min) / 200`.
- The visible label is "Range", wrapped in a [Hint](/editor/ui-hint/): the options block's bar in
  `OperationBody` already names the attribute. `labelFor(target)` from
  [labels.ts](/editor/operation-labels/) still names the attribute in the aria labels. The hint
  is "Soft track" or "Domain", then `min to max`, plus ", wrapping" for a wrapping track; or, when
  collapsed, "A fixed value: the Constant source gives every cell the same number, so both ends
  are one."
- At the end of the block, a `ui/Advisory` with `when={endpointsCoincide(target, mapping)}`: the
  rotation advisory, that the two ends are the same angle so one result lands twice as often,
  and that quarter turns are 0 to 270 in 4 steps. `Advisory` waits until a drag or a typed value
  is committed before it shows or hides it.
- The filled span runs between the two handles whichever way round they are. The handles are
  styled as `Slider`'s ink blocks (`--slider-thumb-w`, `--slider-thumb-h`).
- `setEnd(index, value)`: refused unless `admitsTyped(target, value)`. Sets that end, and the other
  end too when collapsed. Calls `onChange({ ...mapping, range })`.
- Typed ends are [NumericInput](/editor/numeric-input/)s: "From" and "To", or one "Value" when
  collapsed. `parseEnd` refuses blank, non-finite and `!admitsTyped` text, so a half-typed end
  never reaches the draft.
- A [FieldRow](/editor/ui-field-row/) "Values" holds a [Toggle](/editor/ui-toggle/)
  Continuous / Stepped. Its hint says continuous never reaches the far end (`t < 1`), and a flip
  is `-1 to 1 in 2 steps`. `setStepped(true)` sets `steps: mapping.steps ?? MIN_STEPS`;
  `setStepped(false)` **removes the key**.
- While stepped, a NumericInput "Steps" (`step="1"`) whose `parseSteps` accepts only an integer
  `≥ MIN_STEPS` (2).

### Invariants

- **Crossing is legal.** "Preventing the crossing would remove the only way any Source is
  inverted."
- **`steps` absent is a meaning, not a blank.** It is the one field exempt from writing everything
  explicitly, and `steps: null` would be invalid, so the key is omitted.
- **Collapsed means `min === max`.** The alternative, a `value` parameter on `constant`, "would put
  two controls in the UI meaning the same thing".
- **Typed values are checked, never clamped.** Only `opacity` has a bounded typed entry.
- **The rotation advisory never blocks** (**E16**).

### Tests

No test file for the component. `controls/mapping.test.ts` pins every function it calls: the
track table, soft widening and hard non-widening, typed-entry bounds, `MIN_STEPS === 2`, the
rotation advisory, and (with the package's
[`applyNumericMapping`](/api/index/functions/applynumericmapping/)) that stepped `[−1, 1] × 2`
reaches both ends while continuous `[−1, 1]` at `t = 0.5` gives `0`.

### Gotchas & rejected alternatives

- **The track is a drawing decision, not a domain.** Typing beyond a soft track widens it.
- **A collapsed control does not rewrite an uncollapsed range.** `collapsed` only changes which
  handles are drawn and makes `setEnd` write both ends; a range set earlier stays until the author
  moves the single handle.

### Review notes

- `setSteps` has no draft-text model, unlike the two range boxes. Typing `1` on the way to `12`
  is ignored (fine), but an emptied box is not reverted on blur. (inconsistency, minor) **Fixed in
  Block E:** "Steps" is a `NumericInput`, which keeps the in-flight text and shows the value again
  on blur.
- `step = (track.max − track.min) / 200` here, while `affordance.ts` uses `/ 100` for generated
  sliders. Both are UI constants; neither comment mentions the other. (inconsistency, minor)
