## Overview

`FieldRow` is one line of a settings list: the setting's name in large uppercase on the left,
and its control on the right, such as a number field or a set of choice chips. If a setting needs
explaining, the explanation appears when the pointer is over its name, never in the row itself.

## Try it

The real component from `apps/editor`, rendered alone. The story loads the editor's `tokens.css` and `type.css` (but not `base.css`, so the editor's focus ring is not used here) and prints what the component reports.

## In detail

### Public surface

| Prop | Type | Default | Meaning |
| --- | --- | --- | --- |
| `label` | `string` | required | In `.t-label`. |
| `for` | `string` | — | Id of a single native input. When set, the label is a `<label for>`. |
| `align` | `"end" \| "center"` | `"end"` | `end`: control on the label's baseline (underline fields). `center`: for chips. |
| `hint` | `string` | — | Explanation shown in a bubble under the label while the label is hovered. |
| `children` | `Snippet<[string \| undefined]>` | required | The control. Receives the hint's id for its `aria-describedby`. |

### Inputs → outputs

- With `for`: `<label for>`, so clicking the name focuses the input.
- Without `for`: the row is `role="group"`, `aria-labelledby` the label (id from
  `$props.id()`), which names a set of controls such as `Toggle`.
- With `hint`: a `.t-body` bubble (ink background, paper text, at most `--hint-w` wide) sits under
  the label with `visibility: hidden`, and is shown while the label is hovered. It has an id.
  A native `title` was rejected: it appears only after a delay and cannot be styled. A group row puts it in its own `aria-describedby`. A `for` row hands it to the
  child snippet, which puts it on the input.

### Invariants

- **No explanatory text in the row.** Explanations live in `hint`, shown on hovering the label
  (Pol, Block B review).
