## Overview

The palette bar appears in the attribute step of an open operation when the author chooses
Tile (`tileId`), which means the operation places tiles. It is a single horizontal bar cut into
ink segments, one per palette entry. Each segment's width is its share of the total weight, and its
label is the tile's name.

The order of the segments matters. Under a smooth Source such as noise or a gradient,
neighbouring entries become neighbouring regions on the canvas, so water next to sand is said by
putting water next to sand in the bar. The author drags a segment along the bar to reorder it,
or selects one and uses "Earlier" and "Later". Under the bar are a "Tile" picker (including
"clear"), a "Weight" field and a "Remove" button for the selected entry, then "+ Entry" and
"+ Clear". Why order matters is a hint on the "Palette" label.

In the editor's pipeline (import → document → **draft**/history → preview → export), it edits the
draft's palette. It never touches the document.

## In detail

### Purpose

The component edits a [`PaletteEntry`](/api/index/interfaces/paletteentry/)`[]` and reports each
change through `onChange`. The header comment explains why it is a bar and not a list: a Tile's
asset list is sorted by id so that dragging cannot reshuffle the canvas, while a palette's order
is authored and significant (cited as **O6**). "Two adjacent lists in the same editor, with
opposite rules", so the presentation has to make the difference legible. A bar shows adjacency
and proportion in one object, and dragging a segment "reads as rearranging a sequence rather than
sorting a list".

### Public surface

| Prop | Type | Default | Meaning |
| --- | --- | --- | --- |
| `palette` | `PaletteEntry[]` | required | The entries, in authored order. |
| `tiles` | [`Tile`](/api/index/interfaces/tile/)`[]` | required | The library, for names and the picker. |
| `sourceType` | `string \| null` | required | The draft's Source, for the `random` advisory. |
| `onChange` | `(palette: PaletteEntry[]) => void` | required | Receives the whole new palette. |

### Inputs → outputs

- `total` is [`paletteTotal`](/api/index/functions/palettetotal/)`(palette)`, taken from the
  package rather than recomputed.
- **Label:** "Palette" in a [Hint](/editor/ui-hint/). The hint says order matters under a banded
  Source and that a segment can be dragged; under `random` with more than one entry it says
  instead that every value is equally likely, so neighbours mean nothing.
- **Advisory:** a `ui/Advisory` under the bar, "Under the Random source, order means nothing:
  reordering only reshuffles the canvas." It shows only when `orderMeaningless`, the author has
  reordered under the current Source (`reorderedUnder === sourceType`, set in `move`), and no drag
  is in progress (`dragging === null`).
- **Segments:** `flex-grow: weight / total`, ink with paper text. A zero-weight entry gets the
  `zero` class and is drawn as a narrow marker (`--space-2`) rather than vanishing. A `null`
  entry is paper with ink text. The selected entry uses the glyph look (`--color-inactive`). The
  name is drawn inside when the share is over `0.12`.
- **Threshold row:** every entry's name and rounded percentage, in `.t-console`. The selected one
  is underlined.
- **Drag:** `pointerdown` on a segment captures the pointer; `pointermove` on the bar finds the
  segment under the pointer by cumulative share (`indexAt`) and calls `move(from, to)` live.
- **Selected entry:** a [FieldRow](/editor/ui-field-row/) "Tile" with a `<select>` (`""` is
  `null`, shown as "clear"), a [NumericInput](/editor/numeric-input/) "Weight" whose
  `parseWeight` accepts any finite number `≥ 0` and whose hint explains zero weights, and
  [Button](/editor/ui-button/)s "Earlier", "Later" and "Remove", each disabled where it cannot act.
- **Add:** "+ Entry" appends `{ tileId: tiles[0]?.id ?? null, weight: 1 }`; "+ Clear" appends a
  `null` entry.

| Edit | Refused when |
| --- | --- |
| `setWeight` | not finite, negative, or the new palette's total would be `≤ 0` |
| `remove` | only one entry left, or the remaining total would be `≤ 0` |
| `move` | destination out of range or unchanged |

A refusal simply does not call `onChange`.

### Invariants

- **Order is authored and never sorted.** Every edit preserves the sequence except `move`.
- **`null` is an ordinary entry** meaning *clear this cell*. It is offered in the picker beside the
  Tiles and is not a Tile in the library.
- **At least one entry, and a total above zero.** The comment cites the file rule that a palette's
  weights sum to more than zero "or nothing can ever win the walk".
- **Zero weight is legal**, meaning "listed but never chosen".

### Tests

No test file for the component. `controls/mapping.test.ts` pins the palette's surroundings in the
draft: changing Target away from `tileId` and back keeps the palette; an empty palette or one
whose weights sum to zero makes the draft incomplete; a fresh `tileId` draft starts with a legal
`null` entry even when the library is empty.

### Gotchas & rejected alternatives

- **The `random` advisory.** Under a `random` Source values are uniform, so adjacency means
  nothing and reordering "reshuffles the canvas with no visible reason". The bar implies a spatial
  meaning that Source does not deliver. The editor carries this as an advisory rather than having
  two palette presentations. The label's hint changes when `sourceType === "random"` and there is
  more than one entry. The advisory itself shows inline only after the author reorders under
  `random`, and not while a drag is still moving the segment: a line that is always there is a
  line nobody reads.
- **`current` is derived in the script**, not with `{@const}`, which Svelte allows only as an
  immediate child of a block. It is `undefined` when `selected` is stale after a removal.

### Review notes

- **A refused weight leaves the box showing the refused value.** `setWeight` returns without
  calling `onChange`, and the input has no draft-text model like `NumericInput`, so typing `0` on
  the last non-zero entry shows `0` while the palette keeps the old weight. (inconsistency)
  **Partly fixed in Block E:** "Weight" is now a `NumericInput`. `parseWeight` still accepts `0`
  on the last non-zero entry, so the commit reaches `setWeight`, which refuses it; the field
  shows the old weight again once it loses focus.
- The weight input has `step="1"` while weights may be fractional; the browser's spinner moves in
  whole steps only. Harmless, but it suggests integers. (inconsistency, minor) **Fixed in Block
  E:** `NumericInput`'s default `step` is `"any"`.
