# ADR-004 — Vector table regeneration authority during 0.x

**Status:** Accepted
**Supersedes in practice:** the gate in `05` §11 for the duration of 0.x

## Context

`05` §11 permits regeneration of a frozen vector table only alongside a major
bump. `05` §10.3 places all of V1 at `0.x`, where no bump kind binds. The gate
therefore has no release valve for the entire pre-1.0 build, which makes the
first generation of the hash table an irreversible act taken before anyone has
run the code.

## Decision

During `0.x`, any of the five artifacts of `05` §11 / `07` §11.3 may be
regenerated by an explicit, recorded act: a commit that touches only the table
and its regeneration note, with the reason stated in the message.

A test failing against a table is never such a reason. The commit must say what
about the implementation was deliberately changed.

At `1.0.0` this ADR expires and `05` §11's gate binds as written.

## Consequence

The hash family member, `mixLoad`'s operand assignment, the seed string's code
unit access, and the `salt` column's signedness are chosen at implementation and
recorded in code. They are revisable at ordinary cost until 1.0.0.
